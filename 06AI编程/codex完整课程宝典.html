第 1 课 · 001 安装部署与模型接入

本节聚焦"装上、能用"，不讲原理，目标：完成 Codex 安装并能正常对话。

ACodex 安装流程

  1. 确认操作系统：Windows 下载 .exe；Mac 下载 .dmg。
  2. 双击安装包，一路"下一步（Next）"完成安装。
  3. 桌面出现 Codex 图标 = 安装成功。

B首次登录与 API 密钥

  • 首次登录必须选择"使用其他方式登录"——国内网络可直接使用，不依赖 OpenAI 官方。
  • API Key 通过中转网站购买，按需购买（如 10 元 / 58 元对应 10/158 额度），价格浮动以购买时为准。
  • 购买步骤：立即开通 → 填邮箱 → 默认支付宝 → 确认购买。
  • 初学建议先买低额度试用；日常使用多再买高额度。

C密钥保存（一次性关键！）

支付成功后，API Key 仅展示一次，系统提示"此密钥仅展示一次，请务必复制保存"。丢失后无法找回。
  1. 立即点击"复制 APIK"。
  2. 新建记事本（如 codex APIK）粘贴保存。
  3. 确认保存后再关闭浏览器。

D完成登录与验证

  1. 把 Key 粘贴到 Codex 输入框，点"继续"。
  2. 进入主界面后，发送 你是谁？。
  3. Codex 回复"我是 Codex，一个结对工程师" → 安装和配置全部就绪。
关键知识点：登录方式（必须"其他方式"）· 中转网站（不是 OpenAI 官网）· 密钥一次性 · 按需付费 · 验证标准（"我是 Codex"）。

第 2 课 · 002 认识界面，完成第一个任务

前置：001 安装完成。掌握 4 个区域 + 2 种工作模式。

一、四大区域

区域位置功能
左侧侧边栏左新对话、项目、搜索、历史、设置
中间主区域中央发送问题、接收回复（含思考过程）
右侧侧边栏右文件预览、内置浏览器
底部面板底终端

二、左侧栏详解

入口用法
新对话一次性、临时性简单任务
项目（+）复杂、持续性任务；可"新建空白"或"使用现有文件夹"（如桌面简历库）
搜索关键词（Codex/PPT）检索所有历史对话
历史记录回顾与继续之前的对话
设置（齿轮）工作模式 / 权限 / 常规 / 外观 / 快捷键

三、设置中的关键决策

  • 工作模式：编程用户选"适用编程模式"；非编程用户选"适用日常工作"（推荐）。
  • 外观：浅色 / 深色 / 随系统。

四、2 种工作模式心法

简单任务 → 新对话（不关联项目，临时交互）
复杂任务 → 项目（关联文件夹，持续管理）

右侧预览功能在 008 Excel / 009 Word / 010 PPT 中被反复使用——做 PPT / 网页时，无需离开 Codex 即可看到效果。

第 3 课 · 003 把想法变成可执行任务

本节建立贯穿全课的核心心智模型——"老板-员工"。后续 004-014 全都基于此展开。

一、核心心智：你面对的是一个高智商 AI 员工

维度普通聊天 AICodex
交互方式一问一答持续执行、多轮协作
能力边界只能生成文字看项目、操作文件、跑命令
角色定位信息提供者实干型执行者

二、协作法则：反问不是刁难

Codex 反问（如"你想怎么处理？"）= 员工在请示方向，不是让你替他写代码。

角色职责
你（老板）制定方向 · 挑选方案 · 验收结果
Codex（员工）具体技术实现 · 自行想办法完成

三、实战案例：客户礼物分配

  1. 读取并汇报：读取桌面上的客户礼物文件，向我汇报没有领取礼物的客户名单 → 找出 15 人未领取。
  2. 分析并提案：根据他们的积分情况给他们分配礼物，给两个合适的解决方案。
  3. 选择方案并执行：根据方案二新建表格填写好，另存到桌面，命名为客户礼物分配。
  4. 验收结果：桌面是否出现新文件？原文件是否未被修改？

四、关键原则

  • 反问不是刁难：员工请示方向，你做决策。
  • 不关心技术细节：脚本、命令、沙箱都由 Codex 处理。
  • 多方案选择：不确定时让 AI 先出多方案再选。
  • 逐层推进：先信息 → 再分析 → 再执行 → 后验收。

AI 提示词汇总

# 信息获取 读取[文件路径]的[文件名]，向我汇报[需要获取的具体信息]。 # 分析提案 根据[条件/数据字段]给他们[执行操作]，给[N]个合适的解决方案。 # 选择执行 根据方案[N][具体操作要求]，另存到[目标路径]，命名为[文件名]。
提示词设计 5 原则：明确位置 · 明确输出 · 明确数量 · 明确保存 · 逐层推进。

第 4 课 · 004 用技能包扩展能力

前置：003 任务执行模型。本节让你把"反复用的指令"做成永久工具。

一、技能包 vs 提示词

类型作用有效期
提示词 Prompt单次对话内的指令当前对话有效
技能包 Skill把整套流程打包跨对话永久复用

二、三种获取方式

方式一：导入文件（最简单）

  1. 点新对话，把技能包压缩文件粘贴到对话框。
  2. 输入：把这个附件导入成技能包，并检查导入的结果。
  3. 新开对话 → 切换英文 → 输入 / 搜名称 → 调用 → 放材料 → 发送。

方式二：seq hub 仓库搜索（推荐正规渠道）

不要在网上随意下载！推荐 seq hub（国内用户，技能经过检测）。按推荐精选 / 近期飙升 / 下载量 / 收藏量 / 最近上新筛选；按场景分（办公效率、内容创作）。

评估顺序：概述 → 处理原则 → 示例。安装：复制指令 → 新对话粘贴 → 等待完成 → 可改名 请把这个技能名称改为XXX。

方式三：自己创建（实战课展开）

本课不做详细讲解。详见 011 电商详情图 和 012 商品图换品 中的完整 Skill 打造流程。

三、关键操作要点

  • 每次任务新对话：导入、测试都新开。
  • 先阅读说明：每个 Skill 写明了功能与材料。
  • 改名+测试：装完改名便于查找，测试确保可用。
  • 调用方式：英文模式 / + 名称。
安全提醒：不要下载来路不明的技能包，应通过 seq hub 等正规渠道获取。

第 5 课 · 005 权限与安全边界

前置：002 界面（设置面板位置）。本节决定 Codex 能不能做、要不要问你。

板块一：三种内置权限模式

模式机制风险适用人群建议
请求批准敏感操作弹窗确认低新手推荐日常
替我审批自动审核，低风险放行、高风险拦截中中级用户嫌手动繁琐时
完全访问几乎无限制高高级用户临时开启，用完即关

隐藏危险模式

设置 → 常规 → 权限：可关闭"自动审核"和"完全访问权限"的显示，避免误选。

板块二：自定义权限模式（设置 → 配置）

自定义 = 批准策略（问不问）+ 沙盒设置（能不能做）。

批准策略（4 档）

策略含义严格度
不可信几乎什么都要先问最严
失败时普通执行，失败再问中
按请求需要额外权限时问常用
从不尽量不问最宽

沙盒设置（3 档）

沙盒含义场景
只读只能看不能改分析、审查、看代码
工作区写入只能改当前项目日常（推荐）
完全访问可操作项目外临时，谨慎
一句话：沙盒管"能不能做"，批准策略管"做之前要不要问"。
推荐组合：日常 = 工作区写入 + 按请求；代码审查 = 只读 + 按请求；信任任务 = 工作区写入 + 失败时/从不。

板块三：提示词 vs 权限

概念性质作用
权限设置系统级门禁决定能不能做、要不要问
提示词行为约定让 AI 执行前先说明

让 AI 变谨慎的提示词模板：

接下来你在修改文件、运行命令、联网、安装依赖之前，请先说明一下你要做什么，为什么要这样做，以及可能有什么风险，并且等待我的确认。

看不懂批准请求？五步询问法

  1. 先选择"否"，不给权限。
  2. 发送：
我看不懂这个批准请求，请用小白能听懂的话解释一下： 第一，这个操作要做什么。 第二，为什么需要这个权限。 第三，会影响到哪些文件或账号。 第四，如果我拒绝会不会影响任务继续。 第五，你（Codex）是推荐我批准还是拒绝。

第 6 课 · 006 复杂任务先规划：计划模式

前置：003 模型。是"老板-员工"协作的深化。
关联：014 方法二再次强调计划模式节省算力的关键作用。

一、为什么用计划模式

维度普通模式计划模式
启动直接描述需求开启计划模式后描述需求
交互无中间对话，直接出结果先提问澄清 → 出计划 → 确认 → 执行
纠错时机结果出来后计划阶段（成本极低）
修改成本方向错了全部推倒只需改错细节
适用简单任务条件多、步骤多、复杂任务

二、进入方式

  • 菜单：点击 + → 找到"计划模式" → 开关。
  • 快捷键：Shift + Tab 切换。

三、实战：一周晚餐计划

  1. 澄清：Codex 问饮食方式 / 做饭时间 / 用餐人数。
  2. 计划：Codex 出方案，问"是否实施？"
  3. 修正：点"否"+ 反馈（如"不喜欢菌菇"），自动重出。
  4. 执行：确认后提交。
  5. 后续微调：已生成也可继续小修（如"周一晚餐番茄鸡蛋豆腐煲改成番茄炒鸡蛋"）。
核心原则：先规划、后执行——任务多条件、多步骤、复杂 → 必开计划模式。

第 7 课 · 007 一键安装 Python 环境

前置：005 权限（需"完全访问"）+ 003 任务执行。
关联：后续课程反复使用"自然语言驱动系统级操作"的方法。

为什么需要

Windows 默认没装 Python，但 Codex 经常需要跑脚本，必须先装环境。

安装步骤

  1. 打开 Codex，输入：请帮我安装 python 环境。
  2. 给 Codex 授予"完全访问权限"。
  3. 点发送，耐心等待完成。

验证：PowerShell 中运行 Codex 提供的版本检查命令，看到 Python + pip 版本号 = 成功。整过程无需自己下载/配环境变量。

实战：贪吃蛇小游戏

  1. 发送：请用 python 帮我做一个贪吃蛇小游戏。
  2. Codex 自动写完。
  3. 继续：帮我把这个程序在桌面上创建一个快捷方式。
  4. 运行：空格键开始。
完整流程从编程到桌面上出现可点图标，几分钟即可完成。

第 8 课 · 008 自动生成 Excel

前置：003 四步指挥法 + 002 界面预览。
关联：009 Word 四步法 + 010 PPT 五步法。

插件概念

左侧"插件"面板与"技能"不同。默认已安装 Word/PDF/Excel/PPT 插件，办公自动化依赖这些插件。国内网络可能插件显示少，但默认已够用。

实操场景

把出差消费凭证（打车票/高铁票/餐饮截图）整理成 Excel。

核心原则：不要一次性生成

  1. 沟通需求：我有一些出差的支付材料，想整理成 excel 格式，你先帮我整理一下，先梳理出相关的支付费用，等我确定之后再做成 excel。
  2. 精简列：只保留序号、日期、费用类型、金额、支付方式、备注就可以了。
  3. 上传素材：粘贴消费截图，Codex 逐条提取并汇总、自动合计。
  4. 先关后修："T3 出行"应是"在线支付"等小问题后续统一改。
  5. 生成 Excel：现在你按照这个内容整理成 excel。
  6. 引导追加：执行中突然想加"票据单号"列 → 输入新需求 → 点 "引导" 按钮（不中断当前任务合并处理）。
  7. 查看定位：点预览按钮 / "资源管理器"打开复制。

单元格级精准修改（Ask Codex）

  1. 选中目标单元格 → 弹出"Ask Codex"。
  2. 对话框描述修改要求。
  3. 示例：把合计金额放在第七行的后边，开头的这个就去掉（合并行移到末尾）。

可同时选多处、改多处，按编号顺序执行；改失败直接让 Codex 重做（覆盖修复）。生成的文件是标准 .xlsx，支持排序等原生功能。

核心要点

要点做法
沟通策略先探讨、先协商，再生成
引导功能执行中追加不中断
单元格级修改Ask Codex 精准改
多处修改多位置编号顺序执行
容错改失败要求重做

Prompt 速查

1. 我有一些出差的支付材料，想整理成 excel 格式，你先帮我整理一下，先梳理出相关的支付费用，等我确定之后再做成 excel。 2. 只保留序号、日期、费用类型、金额、支付方式、备注就可以了。 3. 现在你按照这个内容整理成 excel。 4. 增加一个票据单号。（执行中用引导追加） 5. 把合计金额放在第七行的后边，开头的这个就去掉。 6. 改成线上支付。

第 9 课 · 009 自动生成 Word（四步生成法）

前置：003 四步指挥法 + 008 分步流程。010 的五步法是它的进化。

场景

"健康减肥食谱" Word 饮食手册。

四步生成法

  1. 初步沟通：我想做一个健康减肥的食谱 word 版，用于指导自己日常饮食。你有什么建议？（Codex 给出五部分目录：目标页/原则/食谱/替换表/避坑清单）
  2. 调整大纲：指定三部分：健康饮食原则 + 早/午/晚各 8 道食谱 + 打卡表。
  3. 确认单样例（最关键）：你先帮我生成一个晚餐的搭配表，只生成一个，我看一下样式是什么样的，确定没问题了，你再整体去生成。
    迭代从表格 → 图+文字（仍表格）→ 图在上、纯文字列表在下，三次才满意。
  4. 整体生成：这次的效果非常满意。你按照这样的效果去做一个完整的 word 版。（28 页完整 Word）

局部修改与图片替换

  • 点击目标位置右侧"问问 Codex"→ 描述修改。
  • 批量替换：把所有的图片改成真实的食材图片。
  • 图片未换：图片没有更换，请检查一下（Codex 会生成新文件名避免缓存）。

核心要点

要点说明
四步生成法沟通 → 大纲 → 单例 → 整体
先出样例再批量用"只生成一个"验证
持续细化排版图位置、表格 vs 纯文本反复迭代
算力节省不一次性生成
缓存处理不生效让 Codex 改文件名

Prompt 速查

1. 我想做一个健康减肥的食谱 word 版，用于指导自己日常饮食。你有什么建议？ 2. 先把目录结构改一下，改成三部分……（按早午晚各 8 道+打卡表） 3. 你先帮我生成一个晚餐的搭配表，只生成一个，我看一下样式是什么样的，确定没问题了，你再整体去生成。 4. 我不喜欢这个样式，我希望你能在上面显示一个图片，下面显示文字……（深入细化） 5. 在 word 排版里边，我希望图片在上面，下方不要用表格的形式……（继续细化） 6. 这次的效果非常满意。你按照这样的效果去做一个完整的 word 版。 7. 把图片中的食材更换成对应的实物图片。比如鸡蛋、番茄、生菜。 8. 图片没有更换，请检查一下。

第 10 课 · 010 自动生成 PPT（五步生成法）

前置：009 四步法 + 008 引导功能。
关联：006 计划模式（"先大纲后做"是计划模式思维）。

场景与素材复用

承接 009 的 Word 文档。Codex 输入 @ + 文档名（如"健康减肥"）→ 自动匹配前次生成结果 → 选中 → 无需重复上传。

五步生成法

  1. 先出大纲：根据这份文档我需要做一个 PPT，你先不要着急帮我做，先根据我的要求做一个目录。
  2. 调大纲：只用展示 8 页就可以。PPT 的风格要符合健康的主题……你帮我重新出一个大纲。
  3. 追加视觉+启动：这次的目录很满意，我希望你在制作 PPT 的时候，多增加一些视觉上的体验……现在你可以制作这个 PPT 了。（先肯定+再补充+最后启动）
  4. 等待自动纠错：编码溢出自动修，绿色主色调健康主题。
  5. 预览与局部修改：预览面板 / 资源管理器放大；Ask Codex 改图；多指令用"引导"按序号排队不中断。

方法论复盘

  1. 先谈需求 → 从目录验证理解。
  2. 调整大纲 → 反复修改直到满意。
  3. 传递视觉意图 → 清晰描述（颜色、氛围、对比）。
  4. 细节微调 → 在版式基础上针对细节。
  5. 中间等就行 → Codex 自动处理编码/溢出。
切记：不要希望通过一句话生成 PPT，效果肯定不好。

Prompt 速查

1. 根据这份文档我需要做一个 PPT，你先不要着急帮我做，先根据我的要求做一个目录。 2. 只用展示 8 页就可以。PPT 的风格要符合健康的主题……你帮我重新出一个大纲。 3. 这次的目录很满意，我希望你在制作 PPT 的时候，多增加一些视觉上的体验……现在你可以制作这个 PPT 了。 4. 换成真实的实物图片。

第 11 课 · 011 一键生成整套电商详情图

前置：004 技能包 + 003 老板-员工模型 + 006 计划模式。
关联：012 姊妹篇（从零生成 vs 模板复用）。

最终效果

输入 1 张产品图 → 输出 5 张完整电商图（2 主图 1:1 + 3 详情图竖版）。儿童碗/服装两类已验证。亮点：模特由 AI 自动生成，无需真人拍摄。

四阶段工作流

阶段核心动作关键技巧
需求沟通告知输入/输出/约束，让 AI 出规划"先探讨再确认"
初步验证上传真实产品，发现第一轮问题提供具体卖点
深度迭代问题 → 链接 → 方案参考链接比文字有效
固化复用满意后封装 Skill，/ 调用中文命名便于查找

关键方法论

  • 五点补充要求：①产品图必填 ②卖点选填（不夸张不编造） ③默认平台某宝/某东/某多 ④风格 AI 自定（食品/服装/日用品色调不同） ⑤禁止修改产品（logo/不变形）。
  • 第一版 4 大问题：文案缺失 → 给同类参考链接；人物不一致 → 显式约束统一形象；画质模糊 → 用"4K 高清摄影风格"；每张都出人物 → 按场景决定。
  • 关键转折：改用 GPT Image 2 一次性生成完整图文，解决中文文案稳定性。
  • 样板验证法：大批量前先出一张样板确认方向。

封装与日常调用

# 封装 你这次做的非常的棒，你帮我把这个做电商产品整套详情图的流程写成一个 skill，面对人的名称为"电商产品详情图"，方便我后边可以直接使用这个命令。 # 日常调用 /电商产品详情图 → 上传产品图（可选卖点）→ 发送 → 约 8 分钟

复杂 Skill 封装 ~10 分钟；错误会被 Codex 自动修复。

完整流程耗时：需求沟通 + 第一轮 + 第二轮 + 批量 8 分钟 + 封装 10 分钟 ≈ 30-40 分钟造一个专属 Skill。

第 12 课 · 012 商品图换品：一键替换，复用模板

前置：004 技能包 + 011 详情图 + 003 老板-员工模型。
定位：011 姊妹篇——从零生成 vs 模板复用。

核心场景

电商设计图已做好，但产品更新换代。希望版式/文字/光影/背景全不变，只换中间产品主体。

两课对比

维度011 详情图012 换品
核心从零生成整套复用模板仅换产品
输入1 张产品图 + 可选卖点2 张图（模板 + 新品）
输出5 张完整设计图1 张替换后的图
封装~10 分钟~3 分钟
执行~8 分钟（5 张）~1-2 分钟
技术点文案/人物一致性/画质透视/光源/服装自然替换

Case 演示

  • 碗具：除碗外一切不变，约 1 分钟。
  • 服装：模特不变，新服装穿到模特身上，约 2 分钟（"非常自然"）。

AI 自主拆解的 5 步流程

  1. 读两张图
  2. 拆图一（位置/光线/大小/保留内容）
  3. 提取新产品特点（正面/侧面/细节）
  4. 执行替换（透视/光源/阴影匹配）
  5. 质量检查（新产品像图二？整体像图一？）

补充约束

只用将图一中的产品替换成图二的新产品，不修改图一的版式、文字卖点等等。除非我提出具体的修改内容。

封装与日常调用

# 封装 把这个流程做成一个 skill，面对人的名称为更换产品图，方便我后边使用。 # 日常调用 /更换产品图 （先传 模板原图 → 再传 新产品图）→ 发送 → 约 1-2 分钟
输入顺序是硬约束：第一张必须是模板原图，第二张必须是新产品图，顺序错就替换错。

关键知识点清单

  1. "先沟通再执行"是 Skill 打造铁律。
  2. 两图输入：图一模板（保留项来源）+ 图二新品（替换项来源）。
  3. 替换范围：仅产品主体。
  4. AI 自动拆解透视/光源/阴影等用户不必懂的专业能力。
  5. AI 主动提问（如"勺子是否保留"）是能力不是缺陷。
  6. 至少 2 个以上品类交叉验证。
  7. 输入顺序不可颠倒。

第 13 课 · 013 智能作图与可视化局部精修

前置：004 技能包安装（与本课插件安装互补）。
关联：011/012 生成的电商图可在此精准精修。

核心问题：文字描述天然不准确

"左上角的人"是哪个角？"那条线"是哪条？文字描述模糊，AI 改不准。

解决方案：Cover 可视画布插件

本地运行画布工具：画圈/画箭头/标注 → 截图 → 发给 Codex → 看图改图一次性到位。

插件安装 5 步

  1. 获取 GitHub 链接（无需理解内容）。
  2. 安全性评估：查看一下这个插件是否可信，告诉我这个插件它主要是做什么的，用最简单的语言总结给我。
  3. 判断安装（Cover = 本地画布，无恶意）。
  4. 执行安装：帮我安装这个插件并启动。
  5. 打开 Codex 侧边栏，浏览器访问本地地址使用。

Cover 画布使用流程

  1. 创建画板与占位框（AI 图片按钮 → 自定义尺寸/比例，如 2:3 = 512×768）。
  2. 生成图片：根据我画布里选中的占位框生成一张 codex 海报并直接插入进去。
  3. 标注并修改：标注工具画线/圈 → 截图 → 按照我截图里的标注修改这张图片。

Cover 优势

  • 视觉标注替代语言描述。
  • 数据存项目本地 cover/，不进代码仓库。
  • 原图不动，迭代方便。
  • 故障排查：装完没出来 → 新开对话；遇到错误 → 为什么有这样的一个错误，你来解决。
公式：安全性评估 → 安装 → 遇到问题让 Codex 自己解决。全程不懂代码也能搞定。

第 14 课 · 014 算力优化与高效工作流

收官课。综合 003/006/008/009/010 的方法论，升华为"算力优化"统一框架。

核心认知：算力浪费的真正来源

算力浪费不是多问一句，而是：需求没说清 / 读了一堆无关文件 / 改了一堆不想改的 / 方向错了整轮返工。

核心口诀：先定范围，再选模式，最后验证交付。

方法一：四要素（任务开始前写清）

要素说明示例
目标要做什么让活动方案变成顾客看得懂的周末说明
上下文读哪些文件只看活动方案
约束不能做什么不改日期、不扩大优惠、不承诺每人赠品
完成标准做到什么程度检查格式 + 总结改了哪里/没改哪里

方法二：复杂任务先开计划模式

请先不要修改文件，请先阅读活动方案草稿，然后告诉我： 你理解的修改目标是什么？你准备保留哪些内容？你准备删减哪些内容？你需要修改哪些文件？哪些地方需要我确认？等我确认后再执行。

关键句：先不要修改文件。执行阶段也收紧范围：现在只修改活动方案草稿，不要修改其他文件，完成后再总结改动和风险。

方法三：把大任务拆小

轮次任务关键点
1只定位问题不改文件
2只改一个明确问题单点修改
3必要检查验证
4总结改动和风险交付

判断：同一文件同一目标 → 同一对话分轮做；不同模块 → 新建对话分别做。

方法四：选模式

任务推荐
改错别字 / 改文案 / 解释内容更快更省
整理文档 / 小范围修改标准模式
复杂架构 / 疑难 bug / 跨文件重构更强模型 + 高推理强度
快速模式响应更快，但比标准模式更耗算力。赶时间才开，日常学习保持标准。

方法五：agents.md 固化规则

把"面向顾客/不夸大/不改日期"等常用规则写到项目目录的 agents.md。新开对话即便不写，Codex 也会自动遵守。

算力消耗全貌

模型选择 + 推理强度 + 上下文长度 + 工具调用次数 + 重复返工 + 快速模式 = 总算力。

最终口诀：小任务直接做，大任务先计划；范围说清楚，上下文少而准；做完要验证，少返工才是真正省。
