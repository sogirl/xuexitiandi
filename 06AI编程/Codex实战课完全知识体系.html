🎯 第三部分：完成 CODEX 的第一技能包

何老师主讲 · 约6200字 · 核心目标：把"技能封装"概念落到具体可跑通的最小案例上

一、技能与技能包概念

技能（Skill）= 可复用的AI流程封装。类比：人会编程、做饭、扫地 = 每项技能 → 打包 = 全能员工。实战案例：视频自动化剪辑 = 剧本→文案→图片→视频→剪辑 = 一个技能包。

二、本期小目标

输入历史人物名字 → 自动输出三件套：①标题（如"千古才女李清照的一生"）②字幕（生平经历，按年龄段划分）③画面描述（每个字幕对应的画面提示词）

三、三大技能详解

技能提示词核心关键设计
写标题"给一个历史人物名字，返回标题" + 模板参考模板 = "风格锚点"（如"秦始皇——统一天下的一生"）
写字幕"返回8段生平经历，格式按年龄+事件"段数可调（7/8/10）、格式可换
写画面描述"每个字幕对应的画面描述≥50字，末尾加'真实古代纪录片风格'"详细度保证出图质量 + 风格统一防止画面跳跃

四、DeepSeek防错提示词（⭐关键）

DeepSeek是纯文本模型——必须加防错提示词！
接下来这个对话窗口一定不要给我返回图片、视频或出现视频或图片的配图和视频。所有内容，一定要直接保存到文件夹中，不要直接展示。
用GPT则无需加此句。

五、技能包封装指令

帮我把整个流程封装成一个技能包。后续用户只需要输入一个历史人物的名字，你就自动输出标题、字幕、生平经历、画面描述。
"Codex 教他只教一遍。"——一次封装→永久复用。

六、提示词五要素结构

任何任务型提示词都包含： ① 任务定义（做什么） ② 格式/模板（按什么范式） ③ 数量/边界（多少字/多少段） ④ 风格/约束（统一性要求） ⑤ 封装指令（是否固化为Skill）

环节模型选择选择理由

首尾帧 = 视频连贯性保障

平台价格

中转 480P约0.23元/秒

关键参数

  • 分辨率：480P（省token）/ 720P / 1080P
  • 时长：5秒一段

数字人合成（对口型）

准备两个元素：音频（语音合成输出）+ 人物出镜视频（自己拍摄的无声视频）。接入中转站对口型模型。

字幕与音频合成

为什么不用开源字幕方案：开源模型做不到"每一句话与时间轴精确对应"——要么整段挤在一起，要么对位不准。最终选用火山引擎做字幕校准。

接入流程：火山引擎控制台开通"语音转字幕"→API文档丢给Codex→提供APP ID+Token→回填→完成接入。

火山引擎的API Key/ID和之前调ChatGPT用的那一套不是同一套，必须在火山引擎自家控制台单独开通、单独拿Key。

封装为Windows本地软件

用 Python Qt（PyQt/PySide）做桌面GUI。产物：EXE文件+依赖文件夹。

🗺 七大核心概念关系

1. Codex工作流核心范式

项目文件夹（隔离工作区） ↓ 挂载文件夹到Codex项目 ↓ 附件投喂（图片/视频/文件） ↓ 下达提示词（任务定义 + 格式/模板 + 数量/边界 + 风格/约束） ↓ 测试驱动（先单条 → 再批量 → 并行提速） ↓ 封装技能包（输入→输出固化） ↓ 后续一键调用技能包

2. 技能包（Skill）封装机制

核心思想：把"想做的一套流程"封装成一个技能；下次只需输入触发条件，技能自动跑完全部流程。

帮我把[整套流程]封装成一个完整的技能包。后续只需要[输入触发条件]，你就可以自动[完整输出]。所有结果直接保存到本地文件夹。

封装价值：一次封装→永久复用 · 团队/客户复用→标准化产出 · "Codex教他只教一遍"

3. API调用方法体系

通用模式： ① 在中转站找模型 → 复制MD文档 ② 在项目文件夹新建.md文件 → 粘贴 ③ 填入自己的API Key ④ 下达提示词："参考这个文档 + 输入素材 + 保存到本地" ⑤ 先单测，再批量
必须用Markdown格式（.md）保存：Codex识别更稳定。必须UTF-8编码：避免乱码。

4. 提示词设计五要素（贯穿所有课程）

  1. 任务定义（做什么）
  2. 格式/模板（按什么范式）
  3. 数量/边界（多少字/多少段）
  4. 风格/约束（统一性要求）
  5. 输出/存储要求（保存位置、格式）

5. "拆解-替换-重组-封装"四字诀

适用场景：女装视频复刻、跨境电商、食品饮料、公众号写作

  • 拆解：用Codex反推原视频的全部要素
  • 替换：把服装/产品替换为自己产品
  • 重组：在保留原风格前提下，用自家素材生成新提示词
  • 封装：将流程固化为Codex技能包

6. "参考对标"信息差打法

找对标（同行爆款） ↓ 参考对标（截图/视频/文章） ↓ 拆解对标（场景/风格/排版） ↓ 替换为我（产品/内容/数据） ↓ AI出图/写文/做视频

★ 七大核心方法论
#方法论核心要点
1"Codex教他只教一遍"给任务+模板+格式+约束→一次说清楚，技能封装后永久复用
2"测试驱动"任何API调用前先单测，再批量。避免浪费token和成本

4"大白话"不需要华丽措辞，把做什么、避免什么说清楚就行。零编程基础也能操作

7"工程化收尾"任何流程跑通后必须封装为技能包——一次性配置永久复用
