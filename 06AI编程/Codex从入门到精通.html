答疑 1：Codex 为什么改名成了 ChatGPT？

Codex 更新后已与 GPT 体系合并，安装完成后看到的应用名称和图标变为 ChatGPT 属于正常产品更新，不是安装包错误。原 Codex 的主要功能、使用逻辑和课程操作仍然有效，可以继续按课程学习。Codex 与 GPT 合并后“里面的功能使用和以前都是一样的”，底层能力、用法逻辑不变。

答疑 2：界面和以前有什么不一样？

整体变化不大，部分位置名称发生调整：

  • 原来叫“自动化”的位置，现已改名为“已安排了”——仍然用于创建重复性、定时执行的工作。
  • 其他面板名称基本保持不变。

安装包打开后仍会跳转到“应用商城”界面（Microsoft Store），直接点击下载即可，后续课程会详细讲解下载与安装步骤。

答疑 3：新增了哪些模型？

模型定位适用场景响应速度
5.6深度推理复杂、推理型工作较慢
ta均衡型日常主力工作中等
露娜 Luna轻量级简单任务最快

选择原则：日常优先 ta，复杂推理用 5.6，轻量任务用露娜。模型只是新增了三个，并未替换原有能力，名字虽变但功能不变。

课前学习方法（02.先导课）

适合三类人：

  1. 在校大学生：以往“很难去做一些拿得出手的项目”，现在通过 Codex 可产出可展示的项目作品。
  2. 在职员工：通过 Codex 自动化功能，把“每天定时定点地为你做一些工作”的计划建好，Codex 按时间点自动执行。
  3. 公司企业老板：用 Codex 搭建可落地的业务工具，实现降本增效。“不怕他做不出来东西，怕的是大家没有一个好的想法”。

课程结构：基础篇（8 节）+ 进阶篇（7 节）+ 案例实战篇（持续更新）。

学习心法：看—学—练三步走。每节课后立即动手练习，不要“看了很多节课之后再做练习”，避免堆积式学习。遗忘时查飞书精炼笔记，形成“视频输入—笔记检索—动手输出”闭环。笔记编号与视频编号基本一致（如 01、02、09、10 两位数编号），二者一一对应。

画质设置：默认是流畅画质，看不清楚。需要在非全屏状态下改为“原画”，全屏状态画质改不了。正确顺序：退出全屏→改原画→重新全屏。

持续更新：AI 迭代速度快，老师会通过加餐课同步新功能和新案例。前面拍了课的同学，无论后续怎么更新，都可以免费学，不受影响。

1.1 安装包下载

实际安装内容来自 03《安装codex》。两种方案：

方案门槛适用人群
中转站 + CC Switch极低，无需 GPT 账号小白、低频体验
GPT 账号直登需要海外网络与账号验证长期高频使用

安装前准备：

  • Codex 主安装包（Windows 或 Mac，Mac 后缀 .dmg）
  • Codex 离线包（备用，处理大部分在线安装失败）
  • CC Switch 安装包（切换模型和中转站的“中控台”，体积仅几十 MB）

Windows 安装顺序：

  1. 双击 Codex 安装包。
  2. 自动跳转 Microsoft Store。
  3. 点击“安装/下载”，等待按钮变为“打开”。
  4. 暂时不要打开 Codex，先配置 CC Switch。
  5. 安装 CC Switch，一路点击“下一步”。

1.2 账号登录

中转站登录（小白首选）
  1. 注册中转站账号，优先选择赠送 20 额度的站点（第二家只送 1 额度，几乎“发两句话就没了”）。
  2. 控制台 → API 密钥 → 创建。
  3. 名称可用 codex-000-111；分组选 codex；过期时间选“永不过期”；额度选“无限配额”；高级设置无需调整。
  4. CC Switch 选择第三个 GPT 图标 → “+” → 自定义配置。
  5. 填名称、API Key、官网/API 请求地址（地址只复制到 v1，不要复制后面的内容）。
  6. 点击“获取模型列表”验证连接（应出现 5.3、5.4、5.4 mini、5.5、image 2 等模型）。
  7. 必须点击“添加”，再点击“启用”——两个动作缺一不可。
  8. 打开 Codex → 选择“使用其他方式登录” → 粘贴 API Key → 继续。
  9. 跳过职业选择（随便选一个职业，会自动安装对应插件）。
  10. 点击 Set up 完成沙箱设置。
GPT 账号直登（05）

长期高频用户可选择官方账号。

成本对比：

项目中转站Plus 会员
计费按 token 量月费 20 刀
额度不限5 小时 150 条
日均5-15 元约 4.7 元
适合短期长期高频（更划算）

Plus 会员价格 20 USD/月（淘宝代充约 160 元/月），掉会员按天退费（约 5 元/天）。Plus 通过家庭共享可降到约 80 元/月。

操作链：

  1. 开启海外网络，访问 ChatGPT 官网（chat.openai.com 或 chatgpt.com）。
  2. 用 QQ/163 邮箱注册，接收邮箱验证码，填写姓名、年龄并跳过引导。
  3. CC Switch 新建 OpenAI 供应商，官网链接和 API Key 都留空（官方直连不需 Key），名称可写 001，点击添加并启用。
  4. Codex 选择“使用 GPT 登录”（不是“使用其他方式登录”）。
  5. 接码平台注册并充值 1 USD（支付宝），密码需大小写字母+数字混合。
  6. 接码平台选服务（OpenAI/ChatGPT）→ 选国家（必须与网络节点国家一致，通常 USA）→ 选运营商 → 复制号码（单价约 0.14 USD，约 1 元多）。
  7. Codex 选择“短信/messages”，不要选 WhatsApp。
  8. 3-5 分钟未收到验证码就取消换号；取消会退款。出现“已切换成 WhatsApp”通常表示号码被注册过，也应取消换号。测试 7-8 个号码属于正常情况。
  9. 5 分钟超时规则：超时后取消换号，不要傻等。
易错点：
  • 节点和手机号国家必须一致，否则收不到验证码。
  • 接码平台人机检测不过 → 关浏览器+重开+重输网址。
  • 号码被注册过 → 显示“已切换成 WhatsApp” → 取消换号。
  • 5 分钟没收到码 → 取消换号，不要傻等。

1.3 初始化设置

首次启动可能需等待 10-20 秒。职业选择可任选并跳过；顶部无关弹窗可关闭。首次英文界面中点击 Set up 完成沙箱设置。发送“你好”，能正常回复即代表配置成功。整个安装过程约 5 分钟可搞定。

1.4 安装失败四级排错（04）

Codex 在 Windows 上“装不上”的根因都归结到“能否顺利进入 Microsoft Store 完成安装”。围绕这一根因，由轻到重的四级解决方案：

第一级：离线包 + 管理员身份运行

  • 下载老师提供的离线安装包
  • 右键 → “以管理员身份运行”
  • 临时关闭防火墙和 Windows Defender 等杀毒软件（避免文件损坏）

第二级：手动打开 Windows Update

  • 设置 → 系统设置 → 安全和更新
  • 启用 Windows 更新（这是 Microsoft Store 依赖的系统级组件）

第三级：第三方小工具强制开启

  • 使用老师提供的 X64 程序（飞书下载）
  • 右键 → 以管理员身份运行 → 勾选“启用更新” → 点击“应用”

第四级：重装系统（兜底）

  • 懂电脑的可以自己重装
  • 不懂的可以去某宝花 30 元请人装，老师说“这种系统比自己在网上下的好用”

2.1 Codex 界面七大区域速览（06）

Codex 界面可分为 7 大区域，老师把它们归纳为「地图课」：

1. 左上快捷区：新对话（Ctrl+N）、搜索、插件、已安排/自动化、移动版。

  • 搜索只能按标题匹配，命名/修改标题很重要。
  • 第一句话会自动成为对话标题，可双击重命名。
  • 插件列表取决于登录方式：GPT 账号可见可用；API 账号可能灰，需额外配置。
  • “已安排”用于每天/每周定时重复性工作。

2. 左下设置区：账号、5 小时和一周双额度、Plus/Pro 升级、编程/日常模式、主题、已归档对话。

  • 双额度耗尽后必须等窗口重置才能继续。
  • 归档不是删除，但无可用网络环境时归档对话可能不可见，应谨慎使用。
  • “适用于编程”或“日常”模式按主用途确定，不需频繁切换。

3. 中部项目/对话区：

  • 项目绑定本地文件夹，适合长期、完整、需保留产出的工作。
  • 对话默认不落本地，适合短期、轻量、临时咨询。
  • 核心判据：“是否沉淀本地文件”。
  • 注意：做完整项目就先建项目。

4. 输入与权限区：推理低/中/高/超高；模型选择；标准/快速速度。

推理档位适用场景
低闲聊、随口问问
中日常普通问答（默认推荐）
高复杂 Bug 修复、难题攻关
超高难度极高任务

快速模式速度是标准 1.5 倍，但 token 消耗是 2 倍，质量不降低。赶时间或额度富裕可用快速。

5. 审批区：请求批准 / 替我审批 / 完全访问权限。

模式规则适用
请求批准（最保守）编辑项目外文件或联网时弹窗请批准新手
替我审批（折中）模型判断低风险自动放行，高风险弹窗中级
完全访问权限（最省心）权限全部放开，不再询问高级

6. 沙箱机制：默认安全护栏，只允许项目工作区内的受限操作、网络访问默认关闭。“完全访问权限”相当于绕过沙箱。

7. 右侧预览区：实时查看网页、文档等成果，可折叠展开。

新手 → 老手 进阶路径：第 1 周用请求批准 → 第 2-3 周用替我审批 → 熟悉后用完全访问权限。

2.2 创建项目（07）

项目本质：带状态的本地文件夹工作流。

创建项目的两种方式：

  1. 新建空白项目：Codex 中点“+” → 新建空白项目 → 命名（如“test 01”）→ 保存。出现重名会自动加 -2 后缀。
  2. 使用现有文件夹（推荐）：先在 D 盘建“codex项目”总目录 → 子文件夹命名（如 test 01）→ 添加到 Codex。可通过“+”选“使用现有文件夹”或直接拖拽。

命名规范：

  • 避免重名（Codex 自动加 -2 后缀）。
  • 使用英文或拼音（中文路径在不同系统易乱码）。
  • 集中归档到专用目录（一个盘 + 一个总目录 + 多个项目子目录）。

多任务并行：

  • 同一对话内连续输入任务会排队顺序执行。
  • 新建多个对话窗口可并行。
  • 跨项目也可并行。

任务状态三标识：

  • 进行中：右侧转圈圈图标。
  • 等待审批：弹窗请用户批准（访问外部资源时触发）。
  • 已完成：小蓝点（点击后消失，类似“未读消息”）。

无项目对话：选择“不使用任何项目”，任务归入日常对话列表。适合临时问答、通用咨询。

2.3 引导功能（08）

引导 vs 排队：

行为含义触发
排队（默认）AI 跑完当前任务，再执行下一条自动
引导用户在 AI 思考过程中，实时插入新指令手动点击“引导”按钮

引导 5 步法：

  1. 下达模糊指令（如“帮我把精选案例里面的图片换一组”）。
  2. 观察 AI 方向。
  3. 补充修正指令，补齐“风格+场景”（如“帮我换成一组意式风格的装修案例图”）。
  4. 点击“引导”按钮（关键动作，不是单纯发送）。
  5. 验证结果。

设置路径：左下角设置 → 编辑器 → 跟进行为。

老师建议：保持排队作为默认，不要切换为引导。

  • 任务耗时长（前面案例 36 分钟）。
  • 批量任务需要排队。
  • 引导可手动兜底。
  • 产品哲学：默认服务高频（排队），手动服务关键低频（引导）。

3.1 目标模式与计划模式（09）

Codex 拥有两种主要的工作模式，分别适用于不同清晰度的需求：

维度计划模式目标模式
需求清晰度模糊明确
任务复杂度高低到中
用户参与度高（需审批）低（仅看结果）
核心收益省 token + 省时间速度快
启用方式加号 → 计划模式加号 → 追求目标

计划模式 6 步法：

  1. 新建项目。
  2. 启用"计划模式"。
  3. 输入模糊需求。
  4. 多轮回答澄清问题（选择题 + 自由补充）。
  5. 阅读并审批 Codex 生成的详细计划（可文字反馈调整）。
  6. 确认后执行。

目标模式 2 步法：

  1. 启用"追求目标"。
  2. 粘贴结构化、目标明确的提示词 → 等待输出。

注释功能（Annotation）：

  • 入口：编辑器右上角"注释"按钮。
  • 流程：框选文字 → 自然语言描述修改 → 提交到对话执行。
  • 价值：点对点精修，局部反馈。
  • 4 步法：打开注释按钮 → 框选/点击文字 → 输入修改要求 → 发送执行。

关键方法论：

  • 模糊需求 → 计划模式。
  • 结构化需求 → 目标模式。
  • 大框架用模式生成，细节用注释功能打磨。

计划模式示例提示词（模糊需求）：

我想做一份员工新员工的入职指南

目标模式示例提示词（结构化）：

（新员工欢迎活动策划方案的详细提示词：包含明确的目标、要求、活动安排、地点、期望达到的效果等）

3.3 给 Agent 制定规则（11）

AGENTS.md 是持久化项目制度：定义角色、输入、流程、输出、原创边界、平台适配、合规、质量验收。

规则三大价值：

  1. 行为可控：减少 AI 随意发挥。
  2. 输出标准化：统一文档结构、表达、交付。
  3. 业务适配：把团队流程写进 Agent 上下文。

两层规则体系：

维度全局规则项目规则
作用范围所有项目当前项目
类比公司总则部门制度
典型内容语言、真实性、通用原则工作流、平台、品牌、禁区
维护频率较低随项目复盘更新

全局配置两种方式：

  • 界面自定义指令（设置 → 个性化 → 自定义指令）。
  • 全局 AGENTS.md 文件（C:\Users\<user>\.codex\）。

项目规则 6 步落地：

  1. 新建独立项目目录。
  2. 选中作为当前项目。
  3. 检查是否已有 AGENTS.md。
  4. 在当前项目上下文生成规则。
  5. 确认文件路径、编码、内容。
  6. 后续任务都在该目录中进行。

核心纪律：先选项目，再生成规则；一个项目一个目录，不混用上下文。

8 类规则内容：

  1. 角色与职责
  2. 输入与上下文
  3. 工作流程
  4. 改写与原创边界
  5. 输出结构与表达
  6. 平台适配
  7. 风险与合规
  8. 质量检查与交付

用计划模式生成规则：用户给角色和大致任务 → AI 追问 → 用户选边界 → AI 出计划 → 审核 → 写入 AGENTS.md。

规则维护闭环：执行项目 → 发现偏差 → 分析原因 → 修改规则 → 下次验证 → 保留有效规则。

我是一名自媒体博主。我每天要做哪些内容？我每天会分析同行的爆款人文案，然后自己去做润色的处理以及。以及一些短视频的运营。工作，请你帮我写一天。写一篇agent。Agents点md文档的规则

4.2 插件和自动化（14）

插件部分：

  • 账号决定上限：GPT 账号可解锁全部插件；API 账号对需授权的插件可能卡死。
  • Gmail 插件 5 步法：搜索 → 添加 → OAuth 授权 → 回链确认 → 功能验证。
  • GitHub + Gmail 组合：空格分隔插件（一句话+多个 /插件），授权过的插件不重复要求授权。
  • 二次授权兜底机制：首次授权未完成时，Codex 执行时会主动提示。

多插件组合示例：

帮我搜寻 GitHub 上近期热度增长速度最快的 10 个 AI 工具，以列表的形式发送到我的邮箱。

自动化部分：

  • 定义：定期触发的对话任务 = 插件调用 + 时间调度。
  • 提示词一键法：四要素 = 触发时间 + 数据来源 + 数据加工 + 数据去向。
每周五五点半的时候重新查询 GitHub 上近期热度增长较快的 10 个 AI 工具项目，整理成中文表格，并通过 gmail 发送到我的邮箱。
  • 手动精细化配置 6 参数：标题、内容、目录、文件夹、频率、时间。
  • 2 个性能调优参数：模型选择（简单任务用 mini）、推理程度（机械任务用低）。
  • 日常维护：优先编辑，不要反复删除重建。

核心心法：

  1. 账号决定上限。
  2. 空格分隔插件（必记）。
  3. 四要素提示词。
  4. 模型按需选择。
  5. 编辑优于删除重建。

5.1 制作网站并发布到公网（18）

完整链路：Codex 写静态网站 → 本地双击 index.html 冒烟测试 → Git 版本控制 → GitHub Public 仓库 → Pages。

使用 Codex 创建旅游网站：

帮我做一个旅游网站

通过计划模式让 Codex 主动反问补全需求（目的类型、内容范围、网站类型、名称、视觉风格），选择"静态网站"最易部署。

本地验证：Codex 文件树 → 三个点菜单 → 在资源管理器中打开 → 双击 index.html → 浏览器能正常打开。

Git 安装与验证：

git --version

安装 Git 后，在项目地址栏输入 cmd，用 dir 核对目录。

Git 本地初始化与基础配置：

git init
git config --global user.name "X"
git config --global user.email "Y"
git status
git add .
git commit -m "first"

Git 三段式：工作区（红）→ 暂存区（绿）→ 仓库（白）。

GitHub 仓库创建：

  • 优先用谷歌邮箱注册（GitHub 谷歌邮箱一键登录体验最顺滑）。
  • 仓库名必填，可能需加后缀。
  • 必须 Public（GitHub Pages 免费托管前提）。
  • 不勾选 README / .gitignore / license。

git remote add origin <URL>
git remote -v
git push -u origin master

若分支为 main，最后一行改为 git push -u origin main。首次推送需 OAuth 授权登录与邮箱验证。

GitHub Pages 发布：仓库 → Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main / master → 路径 / (root) → Save。等待几分钟 → 获得 https://<user>.github.io/<repo>/ 网址。

5.4 制作小游戏（21）

核心方法论：

  • 自然语言即代码。
  • 迭代而非一次成型（生成 → 试玩 → 反馈 → 优化）。
  • 结构化先行（先想清楚需求和命名）。
  • AI 协作写提示词（手写框架 → AI 优化 → 复用）。

两轮迭代展示：

第一轮（外观 + 基础体验）：棋盘从 3 排扩到 6 排、每排多 3 个格子、加背景音乐 + 打击音效、优化植物/怪物外形。

第二轮（玩法机制）：阳光机制重构（自动获取 → 天降 + 鼠标点击拾取 + 5 秒衰减）、多植物系统（1 种 → 3 种）、双连发植物。

自定义素材目录结构：

项目根目录/
├── index.html
├── style.css
├── script.js
└── assets/           ← 素材资源根目录
    ├── background/   ← 背景图片
    ├── plants/       ← 植物素材
    ├── zombies/      ← 怪物素材
    ├── bullets/      ← 子弹素材
    └── ui/           ← 界面素材

命名铁律：文件夹与素材名一定不要用中文（中文路径在不同系统下易乱码，GitHub Pages URL 不稳定）。

Git 发布 7 步法（与 5.1 互补）：

  1. 开终端。
  2. 绑定仓库（每次换文件夹必须重做）。
  3. 添加文件夹内容（git add <文件夹>/ 末尾必须加斜杠）。
  4. 检查添加结果（绿色 = 成功）。
  5. 提交（commit）。
  6. 推送到 GitHub。
  7. 刷新 GitHub 仓库验证。

链接拼接公式：仓库 Pages 基础 URL + /子目录名。

延迟容错：push 后等 3-5 分钟再访问。

5 大避坑：

  • ❌ 不要用中文命名文件夹。
  • ❌ 不要指望一版定稿。
  • ❌ 换文件夹后忘记重新绑定 GitHub 仓库。
  • ❌ git add 漏掉末尾斜杠。
  • ❌ push 完立刻访问链接打不开就放弃。

维度纯提示词素材辅助音画同步

制作周期15-30 分钟20-40 分钟30-60 分钟
适合快速测试、批量产品展示、品牌视频专业讲解、品牌宣传

5.6 Remotion 高阶玩法（23）

Remotion 用 React + TypeScript 描述视频帧，自动生成可播放导出的视频产物。

环境准备：

  • 必装 Node.js（React + TypeScript 的运行环境）。
  • 验证：node -v。
  • Codex 让 AI 自动安装 Node.js。

提示词五层结构：

  1. 总体要求（做什么、为什么做、什么水准）。
  2. 技术栈指定（Remotion + React + TypeScript）。
  3. 时长与分辨率。
  4. 风格约束。
  5. 时间分段（核心技巧）。

3+9+12 秒分段法（或任意 N 段均分法）：

  • 0-3 秒：开场吸引（Logo + 标题 + 钩子）。
  • 3-6 秒：第一段内容（主图 + 功能介绍）。
  • 6-9 秒：第二段内容（主图 + 多个功能卡片）。
  • 9-12 秒：结尾收束（Logo + 总结文案 + 引导）。

AI 协作方法论：

  1. 手动列大纲（每段写什么）。
  2. 写风格约束。
  3. 写技术约束。
  4. 交给 GPT/Claude 做细节优化。
  5. 把优化版投入 Codex。
最大坑点（必避）：
永远不要在提示词里写 @emotion / @remotion！
直接用自然语言"请使用 Remotion 帮我……"。否则会转圈卡顿 10-20 分钟。

素材整合三要点：

  1. 明确素材清单并提前拖入对话窗口。
  2. 明确要求素材存到项目文件夹（assets/）。
  3. 时间分段映射与第一版保持一致。
素材处理铁律：
  • 素材必须语义化命名（main-image、logo、voice）。
  • 素材必须放在项目文件夹的子目录（assets/）。
  • 素材清单必须在提示词中明确列出。

底层逻辑：Codex 是 Coding Agent，在项目文件夹里读+写+改+运行最稳定。

6.1 Codex 电商应用（24）

用 Codex 搭建电商独立站（演示课：卖女包）。

三大核心工具：

工具定位角色
Next.js前端框架商品页、详情页、购物车、下单页
Stripe在线支付收款、生成支付结果、回写订单状态
Supabase数据库 + 用户系统保存商品、订单、用户数据

架构关系：Next.js（门面） → Supabase（仓库） → Stripe（收银台） → 状态回写 Supabase。

7 步搭建流程：

  1. 新建项目并打开计划模式。
  2. 写提示词（"卖女包独立站"）。
  3. 交互式补充需求（风格、语种、登录）。
  4. 等待执行。
  5. 查看成品。
  6. 上传新商品。
  7. 验证支付链路。

冷启动提示词：

帮我做一个卖女包的独立站，包含详情页、商品列表、购物车。
关于我们联系我们。
（首版先不要求用户登录注册；支持中英双语；风格"高级简洁"）

图生商品提示词（多模态输入）：

帮我把这两个包上传到网站的商品栏里。商品栏然后我们给到一个价格，
价格的话橘色的包售价 8999，黑色的 85 售价 12888。

图片直接拖入对话框，Codex 自动识别商品名、材质、尺寸、颜色、库存。

6 大方法论：

  1. 工具认知先于语法。
  2. 计划模式是习惯。
  3. 提示词分两段写（业务范围 + 追问补全）。
  4. 迭代优于一次成型。
  5. 多模态输入可加速。
  6. 搭站只是起点。

关键提醒：

  • 演示版没有 Stripe 密钥，真正收款需另外配置。
  • 后续可与 Remotion（5.6 节）组合做"独立站 + 短视频 + 投流"闭环。
  • 课程性质说明：本课是"卖女包"演示载体，不构成实质性的选品分析。

6.2 Codex 辅助室内外设计（25）

室内外设计前期概念方案。

传统谈单 3 大痛点：

  1. 客户缺乏空间想象力（CAD 难懂）。
  2. 同质化竞争导致价格战。
  3. 设计师在客户心智中位置偏低。

Codex 可覆盖的 5 项前期能力：

  1. CAD 平面图转彩屏图（1:1 复刻）。
  2. 空间概念效果图（360 全景）。
  3. 设计理念文案。
  4. 报价逻辑 + 服务流程说明。
  5. 客户汇报 PPT/PDF/网页。

6 步签单流程：

  1. 收集客户资料。
  2. Codex 生成概念性方案框架。
  3. 做彩屏图和功能分区。
  4. AI 工具生成效果图。
  5. Codex 整理成 PPT/PDF/网页。
  6. 配合成交话术。

人机分工边界：

  • AI 解决"中段可视化与文案"高耗时环节。
  • 第 1 步（资料收集）和第 6 步（成交话术）仍是设计师职责。

CAD → 彩屏图提示词：

使用codex内置的image模型帮我做彩屏图。
彩屏图针对上方提供的CAD CAD户型做出对应的彩屏。
布局一定要1比1，复刻一定要一第一复刻。
CAD的平面布置图。

彩屏图 → 360 效果图提示词：

基于上面的做好的彩屏图，去帮我做几个空间的360效果图。
其中包含客餐厅、主卧衣帽间。衣帽间好，我们就做三个空间。
…新中式的新中式风格整体的框架一定要和平面彩屏图保持一致。

360 全景提示词：

做好了之后再帮我生成在本地可以运的360的效果。

线稿深化提示词：

基于这个线稿去帮我做一张效果图。
结构一定要按照线稿的结构一比一去生产，1比1比1去生产。
风格还是按照前面的前面的，按照上面做的风格去生成。

关键经验：

  • 必须显式提示"360/全景"才会得到全景预览，否则只是普通透视图。
  • 360 接缝问题已被新一代 AI 解决。
  • 平面与立面对齐仍需"推理档位 + 多次迭代"。

成本对比：

路径耗时成本
传统1-2 天建模 + 2-5 天渲染每张 200-800 元
AI30 分钟以内 + 5-10 分钟修正接近零成本

6.3 基于 Codex 做 RAG 知识库（26）

RAG（Retrieval-Augmented Generation，检索增强生成）= 让 AI 在回答用户问题之前，先去用户预先准备好的资料库里"查一查"，再根据查到的内容生成回答。

适用场景：客服自动问答、企业知识库、产品资料问答、FAQ 自动回复。

4 步法：

第一步（搭框架）：用提示词让 Codex 生成 RAG 项目骨架：

请帮我创建一个 RAG 知识库演示项目。

项目目标：用于教学演示，让用户理解 RAG 的基本原理。
核心目的：用户提问后，系统先从本地知识库查找相关内容，再根据内容生成答案。

技术要求：
[填写你的技术要求]

项目结构：
- 项目根文件夹
  - package.json（项目配置/说明书，给机器看）
  - server.js（核心代码，RAG 系统的大脑和发动机）
  - knowledge.txt（知识库文档，存放所有产品资料）
  - README.md（项目说明，给人看的）

第二步（入资料）：把现有资料整理成 RAG 友好的 7 标准板块：

  1. 产品介绍
  2. 适合人群（人群画像）
  3. 核心功能
  4. 价格说明
  5. 购买流程
  6. FAQ 常见问题
  7. 人工客服规则

第三步（跑测试）：覆盖业务问题与越界问题。

请帮我测试 RAG 知识库是否能够正常运行。

测试覆盖以下问题：
- 这个产品是什么？
- 这个产品多少钱？
- 付款后多久开通？
- 可以退款吗？
- 怎么联系人工客服？
- 你们能开发火箭吗？

期望结果：
- 命中知识库的问题：正常返回答案
- 未命中知识库的问题：建议转人工

第四步（细拆分）：把单文件升级为多文件知识库。

请帮我把当前的 RAG 项目从单个 knowledge 文档升级为简单的多文件知识库，方便今后管理。

要求：
- 不要拆得太细
- 拆解为以下三个文件：
  1. 产品资料
   2. 常见问题
  3. 售后规则
- 把对应资料分别保存到对应文件

核心价值：把"半天到一天"压缩到"几分钟"，让非工程师也能落地 RAG 知识库。

核心收获：

  • RAG 不是 AI 记住了资料，而是 AI 在回答前能查到资料。
  • Codex 让 RAG 搭建从"专业工程"变成"提示词工程"。

6.4 RAG 客服智能体（27）

RAG 知识库 + 客服智能体封装。

客服智能体 = 三部分组合：

  • 用户提问入口（前端交互层）。
  • RAG 回答逻辑（业务处理层）。
  • 回复展示与发送（输出层）。

核心比喻：RAG = 客服的"大佬资料"（静态），智能体 = "前台客服"（动态）。

MVP 优先策略：先本地演示版 → 再换皮到企微/网页/小程序 → 最终上线。

项目结构升级：

RAG 知识库项目根目录
├── 后端代码（已有）
└── public/ （本节新增）
    ├── index.html
    ├── style.css
    └── script.js

第一步：前端聊天页面（用 Codex 提示词驱动生成）：

给项目增加一个聊天的页面，前端用我们已经有的接口即可，页面展示 AI 客服的回复，并增加"转人工"的提示。

页面展示 AI 客服回复，增加"转人工"提示是关键设计。

"截图即问题、AI 即修复"开发范式：

  • 遇到 bug → 截图 → 丢给 Codex → 自动修复 → 再测试。
  • 不要靠人脑 debug，让 AI 去 debug。

多 AI 协作架构：

AI角色典型场景
Codex工程师写代码、改代码、重构项目
GPT顾问答疑解惑、配置咨询、报错诊断
RAG + 大模型客服回答真实用户问题

3 个实测业务问题：

  • 产品介绍 → 标准回答。
  • 退款问题 → 智能体主动建议转人工（关键设计）。
  • 开通时效 → 标准回答。

转人工机制（安全阀）：AI 不确定时主动导流，避免错误承诺。

企微接入流程（未来落地路线图）：用户消息 → 企微服务器 → 业务服务器回调 → RAG 生成 → 企微 API 回复。与本地版区别仅在"接入层"，RAG 业务内核不变。接入需要：云服务器、企业微信账号、回调 URL、签名验证、代码部署。

7.1 Codex 结合飞书 CLI 办公（28）

飞书 CLI 是 Codex 的"手脚"：Codex 理解意图，CLI 调用飞书 API。

核心比喻：

  • 大脑 = Codex（理解意图、生成步骤）。
  • 手脚 = 飞书 CLI（调用飞书底层 API）。
  • 工作环境 = 飞书 App。

安装 6 步流水线：

官网登录 → 选择安装方式（推荐智能体）
   ↓
复制提示词 → 粘贴给 Codex → 自动安装
   ↓
应用配置（一次性链接 + 浏览器内开通）
   ↓
用户授权（二维码 / 链接 二选一）
   ↓
回复"完成"×2 → 检查通过
   ↓
7 天周期自动延期机制

7 天延期机制：7 天内使用过自动延期；7 天内没使用授权作废。

两种身份：

  • 应用身份：让 CLI 自己跑后台任务，文档归属为机器人。
  • 用户身份：让 CLI 模拟你的操作，文档归属为你。

权限开通：飞书开发者后台 → 权限管理 → 开通权限。或"用到再开"，Codex 会现场提示。

7.3 Computer Use：AI 操控电脑（29）

Computer use 可看屏幕、点击、输入和滚动，但当前稳定性低、速度慢、token 高、截图上传存在隐私风险，只适合非敏感尝鲜。

OpenAI 官方定义：AI 通过看屏幕理解界面、点击鼠标、输入键盘、滚动页面代替人操作。

当前使用感受（"只能当玩具"）：

  • 痛点 1·效率：打开微信发一条消息就需要几分钟。
  • 痛点 2·成本：运行时间越长，token 消耗越多。
  • 痛点 3·安全：AI 截图会传后台，输入账号密码存在隐私泄露风险。

老师实测 3 缺点：稳定性低、速度巨慢、风险性高。

未来展望：

  • 语音输入 + 电脑操控 = 真正"动口不动手"。
  • 免费账号无麦克风图标；会员账号才有语音输入。

GPT 账号开启方式：

  • 路径 1：插件商店 → computer use 和浏览器操控 → 安装。
  • 路径 2：设置 → 电脑操控 → 开启两个插件。
  • 额外步骤：浏览器功能需安装 Chrome 扩展程序。

微信发消息实测（1 分多钟）：

  • 屏幕变蓝（AI 在控制电脑的视觉提示）。
  • AI 用内置虚拟鼠标。
  • 联系人名字打错一字仍能识别。
  • 必须前置打开聊天窗口（大幅减少 AI 定位时间）。

提示词（微信发消息）：

打开我的微信，然后给大宇老师助手发一条你好这个消息。

API 登录同学解决方案：安装 Codex CLI（Codex 加加）（回看 4.1 节）。

评估新 AI 功能的 6 维度：方向、稳定性、速度、成本、安全、当前定位。

7.4 手机远程连接 Codex（30）

核心痛点：出差、通勤、外出时无法守着电脑，但又不想中断项目进度。

关键前提：电脑必须保持开机 + Codex 软件运行 + 网络工具链路畅通。

4 步配置：

步骤 1（前置准备）：

  • 准备网络工具（必备前置）。
  • iOS 需海外 Apple ID（借公用 ID 或租借）→ 切换回自己账号。
  • Android 通过 Google Play 下载。

步骤 2（桌面端配置）：

  • 入口位置：第一次在左侧菜单栏，配置过后迁移到左下角小手机图标。
  • 点击入口 → 弹窗向导 → 连续点"下一步" → 生成二维码。

步骤 3（手机端扫码）：

  • 用支付宝扫码 → 复制链接 → 浏览器粘贴 → 点击前往。
  • 手机端网络工具必须切到"全局模式"（不是智能模式）。

步骤 4（账号登录）：

  • 手机端与电脑端必须登录同一个账号。
  • 一次性配置成功后无需重复扫码。

连接成功标志：

  • 项目列表同屏可见。
  • 消息双向同步。

远程任务下发实测：

  • 游戏项目小修小补（"再帮我优化一下画面"）。
  • 飞书表格操作（"帮我删除一栏"）。

8.1 Codex 外接模型做视频（31）

外接第三方视频生成模型做电商带货视频。让 Codex 阅读任意 API 文档，生成 SKILL.md + config.json + scripts/，再把 APIKey 填入并装到 ~/.codex/skills/。

三套可行方案：

  1. 自建 Skill 方案：Codex + MiniMax 海螺 API 自己配置。
  2. 即梦官方 CLI：门槛太高（年 1959 / 月 649）。
  3. LipTV 第三方平台（推荐）：59 元/月可调 C 端 2.0。

核心能力链路（自建 Skill）：

  1. 接收产品图片 + 时长要求。
  2. 分析图片（外观、功能、卖点、痛点）。
  3. 生成分镜图（6 秒/张）。
  4. 写图生视频提示词。
  5. 写口播文案。
  6. 调用外部模型。
  7. 合成成品。

自建 Skill 5 步流程：

  1. 下载插件包 + 模板文件。
  2. 找到海螺官网 API 文档（认准官网）。
  3. 用提示词让 Codex 干活（设定 Codex 角色 + 目标 + 文件结构 + 输出位置）。
  4. 填入 APIKey（只显示一次，必须立刻保存）。
  5. 安装到 ~/.codex/skills/。

核心方法论：让 Codex 读任何 API 文档，自动产出 Skill——这是通用方法论，可迁移到任何外部 API。

测试 → 调优循环：

  • 用 Codex 改 Skill 比手改更高效。
  • 反复测试 → 找问题 → 让 Codex 改 → 再测试。
  • 烧钱是必经之路（视频模型成本高）。

## 终极系统性总结

课程核心知识体系
